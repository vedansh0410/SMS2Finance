## 📖 Executive Summary & Motivation

In modern mobile banking ecosystems—particularly across India's Unified Payments Interface (UPI) network—Short Message Service (SMS) notifications generated by financial institutions represent the primary, real-time ledger of consumer financial activity. Every card swipe, UPI QR transfer, ATM cash withdrawal, IMPS transfer, and corporate salary credit produces an automated SMS alert.

However, extracting structured transaction logs from raw mobile SMS presents three major hurdles:
1. **Pervasive Inbox Distractor Noise**: Legitimate transaction alerts are drowned out by transient authentication One-Time Passwords (OTPs), promotional loan offers, and marketing spam.
2. **Privacy Exposure & Bandwidth Waste**: Uploading a user's entire uncurated SMS inbox to cloud servers exposes private conversations and authentication codes while wasting cellular bandwidth.
3. **Template Fragility vs. Contextual Variance**: Deterministic regular expressions break when banks modify template phrasing, while pure statistical Named Entity Recognition (NER) models struggle with rigid 12-digit Retrieval Reference Numbers (RRNs) and floating currency amounts.

**FinSight AI (SMS2Finance)** solves this trilemma with an end-to-end multi-tier pipeline:
* **Edge-Device Level-1 Filtering (Algorithm 1)**: Heuristically drops non-bank spam, marketing loans, and authentication OTPs directly on the Android smartphone before transmission.
* **Fault-Tolerant Incremental Sync**: Enforces a strict 30-day sliding window and chronological oldest-to-newest synchronization gated by an on-device `lastSync` timestamp checkpoint.
* **Hybrid Information Extraction (Algorithm 2)**: Reconciles deterministic regex precision for rigid structural entities (`AMOUNT`, `RRN`, `ACC_NUM`, `UPI_ID`, `BALANCE`) with statistical NER token classification for high-variance contextual entities (`MERCHANT`, `TXN_TYPE`).
* **Tiered Financial Deduplication (Algorithm 3)**: Combines deterministic RRN matching with temporal composite Jaro-Winkler string similarity to eliminate duplicate records with a **0.0% false-merge rate**.
* **Real-Time Analytics Dashboard**: Visualizes income/expense trends, institution distributions, merchant leaderboards, and an interactive extraction provenance inspector.

## 🔬 Formal Algorithms Summary

Detailed mathematical proofs and complexity bounds are available in [`doc/17_FORMAL_ALGORITHMS.md`](file:///c:/Users/HP/Downloads/SMS2Finance/doc/17_FORMAL_ALGORITHMS.md):

### Algorithm 1: Edge-Device Level-1 Bank Transaction Filter
* **Location**: [`sms-android/app/src/main/java/com/vedansh/smssync/filter/BankSmsFilter.java`](file:///c:/Users/HP/Downloads/SMS2Finance/sms-android/app/src/main/java/com/vedansh/smssync/filter/BankSmsFilter.java)
* **Logic**: Evaluates bank header prefixes $\mathcal{H}_{bank}$, discards promotional spam and isolated OTPs $\mathcal{K}_{exclude}$, validates transaction intent keywords $\mathcal{K}_{txn}$, and confirms currency pattern $\mathcal{P}_{currency}$.
* **Empirical Result**: **32.91% Bandwidth Reduction Ratio** with **0.0% False Negative Rate**.

### Algorithm 2: Conflict-Aware Entity Reconciliation
* **Location**: [`ai-ml/normalization/reconciliation.py`](file:///c:/Users/HP/Downloads/SMS2Finance/ai-ml/normalization/reconciliation.py)
* **Logic**: Fuses candidate sets from deterministic regular expressions and statistical NER models. Enforces **deterministic priority** for rigid structural fields (`AMOUNT`, `RRN`, `ACC_NUM`, `UPI_ID`, `BALANCE`) and **contextual priority** for high-variance fields (`MERCHANT`, `TXN_TYPE`) above confidence threshold $\theta_{ner} = 0.75$.
* **Empirical Result**: **0.9400 Macro F1** exact span match across 6 major Indian banks.

### Algorithm 3: Tiered Financial Transaction Deduplication
* **Location**: [`ai-ml/deduplication/tiered_dedup.py`](file:///c:/Users/HP/Downloads/SMS2Finance/ai-ml/deduplication/tiered_dedup.py)
* **Logic**:
  - **Level 1**: Deterministic unique key match on RRN ($\ge 6$ chars) executed in $O(1)$ amortized time.
  - **Level 2**: Composite fuzzy-temporal match ($Amount \times Type \times AccLast4 \times \Delta t \times \text{Jaro-Winkler}(\text{Merchant}) \ge 0.85$) when RRN is absent.
* **Empirical Result**: Eliminates duplicate ledger records with **0.0% False-Merge Rate**.

## ❓ Frequently Asked Questions (FAQ) & Troubleshooting

<details>
<summary><b>1. Why does Android show "Connection refused" or network timeout?</b></summary>
Android emulators access your computer's localhost via <code>http://10.0.2.2:8080/</code>, not <code>localhost</code>. If using a physical phone, you must provide your workstation's LAN IP (e.g., <code>http://192.168.1.50:8080/</code>) in <code>RetrofitClient.java</code> and ensure both devices share the same WiFi network.
</details>

<details>
<summary><b>2. Why does the dashboard show data if my backend isn't started?</b></summary>
The React frontend includes an automatic graceful fallback in <code>frontend/src/services/api.ts</code>. If the Spring Boot backend is unreachable, the dashboard renders verified, realistic benchmark data so you can inspect charts and test UI workflows offline.
</details>

<details>
<summary><b>3. Why is regular expression matching not called an AI model?</b></summary>
In accordance with research integrity standards, regular expressions are deterministic string-matching rules. In this project, extraction is formally defined as a <b>hybrid information extraction framework combining contextual machine-learning NER token classification with deterministic rules</b>.
</details>

<details>
<summary><b>4. How does the system prevent merging distinct identical-amount transactions?</b></summary>
Per Algorithm 3, transactions are never deduplicated by amount alone. Deduplication requires either an identical 12-digit Retrieval Reference Number (RRN) or a composite temporal match satisfying identical account last-four, identical transaction direction, receipt within a 1-hour temporal window, and a high Jaro-Winkler merchant similarity score ($\ge 0.85$).
</details>
