\title{SMS2Finance: An Edge-Filtered Hybrid NER and Rule-Based Framework for Structured Financial Transaction Extraction from Bank SMS}

\author{\IEEEauthorblockN{Anonymous Authors}}

\maketitle

\begin{abstract}
Short Message Service (SMS) notifications generated by financial institutions constitute an ubiquitous source of personal transaction records in digital payment ecosystems such as India's Unified Payments Interface (UPI). However, their semi-structured syntax, high volume of non-financial distractors (e.g., authentication OTPs, promotional marketing), and sensitive financial contents present critical challenges for server-side processing and user privacy. In this paper, we propose SMS2Finance, an end-to-end framework combining on-device Level-1 heuristic filtering, incremental timestamp-checkpoint synchronization, and a hybrid backend parsing engine. Our extraction module fuses deterministic regular expressions with contextual Named Entity Recognition (NER) token classification to resolve high-variance entities such as dynamic merchant descriptors and retrieval reference numbers (RRN). Furthermore, we propose a tiered deduplication algorithm that eliminates redundant records without cross-transaction false merges. Evaluated on a curated, differentially anonymized benchmark of 2,500 real-world Indian bank messages across six major institutions, SMS2Finance reduces edge-to-server data transmission by 32.91\% with a 0.0\% false negative rate, achieves an entity extraction macro F1-score of 0.9400, and maintains a 0.0\% false-merge rate.
\end{abstract}

\begin{IEEEkeywords}

\section{Introduction}
In emerging digital economies, cellular SMS notifications generated by commercial banks represent the primary real-time record of consumer financial activity. Each debit card swipe, UPI QR transaction, ATM withdrawal, and direct salary deposit triggers an automated notification. Mining these notifications enables automated Personal Financial Management (PFM), fraud detection, and credit scoring.

However, extracting structured ledgers from mobile inboxes incurs three fundamental challenges:
\begin{enumerate}
    \item \textbf{High Distractor Density}: Financial inboxes are inundated with transient authentication codes (OTPs) and promotional loan spam.
    \item \textbf{Privacy and Bandwidth Costs}: Transmitting uncurated SMS inboxes to cloud servers exposes private conversations and authentication codes.
    \item \textbf{Template Brittleness vs. Generalization}: Rigid regular expressions break under template shifts, while pure statistical NER models struggle with rigid 12-digit transaction hashes and monetary values.
\end{enumerate}

To overcome these barriers, we introduce \textbf{SMS2Finance}, a four-tier architecture combining on-device edge filtering, fault-tolerant ingestion, hybrid NLP extraction, and interactive financial visualization.

\section{System Architecture}
The SMS2Finance architecture partitions workloads across four decoupled layers:
\begin{itemize}
    \item \textbf{Mobile Edge (Android SDK 34 / Java)}: Performs on-device heuristic pre-filtering and maintains an incremental $lastSync$ checkpoint in local storage.
    \item \textbf{Backend Ingestion (Spring Boot / Java 21)}: Provides idempotent REST ingestion, persists raw audit logs in PostgreSQL, and orchestrates extraction.
    \item \textbf{AI/ML Extraction Service (FastAPI / Python)}: Executes deterministic regex matching, contextual NER token classification, conflict-aware reconciliation, and tiered deduplication.
    \item \textbf{Client Dashboard (React 18 / TypeScript)}: Delivers real-time cash flow analytics, merchant leaderboards, and an entity provenance inspector.
\end{itemize}

\section{Methodology \& Formal Algorithms}

\subsection{Algorithm 1: Edge-Device Level-1 Filter}
Let an incoming message be $M = (s, b, t)$ where $s$ is the sender header, $b$ the body, and $t$ the device timestamp. We define verified bank header prefixes $\mathcal{H}_{bank}$, promotional exclusions $\mathcal{K}_{exclude}$, and transaction triggers $\mathcal{K}_{txn}$. The filter discards non-bank and distractor messages locally before network transmission, guaranteeing zero data leakage.

\subsection{Algorithm 2: Conflict-Aware Entity Reconciliation}
Deterministic regex candidates $\mathcal{E}_{reg}$ and statistical NER candidates $\mathcal{E}_{ner}$ are reconciled using a domain priority hierarchy. Rigid structural entities ($\text{AMOUNT}$, $\text{RRN}$, $\text{ACC\_NUM}$, $\text{UPI\_ID}$) prioritize deterministic extraction, while variable contextual tokens ($\text{MERCHANT}$, $\text{TXN\_TYPE}$) prioritize NER classification above confidence threshold $\theta_{ner} = 0.75$.

\subsection{Algorithm 3: Tiered Financial Deduplication}
To prevent ledger duplication without false merges, transactions are evaluated through a two-tier hierarchy:
\begin{itemize}
    \item \textbf{Level 1}: Deterministic unique key matching on RRN ($\ge 6$ digits) in $O(1)$ time.
    \item \textbf{Level 2}: Composite temporal fuzzy matching on $Amount \times Type \times AccLast4 \times \Delta t \times \text{Jaro-Winkler}(\text{Merchant}) \ge 0.85$ when RRN is missing.
\end{itemize}

\section{Experimental Evaluation}

\subsection{Benchmark Dataset}
We evaluate on a curated benchmark of 2,500 messages stratified across:
\begin{itemize}
    \item Debit UPI transactions: 35\% (875 messages)
    \item Debit Card/ATM/IMPS: 15\% (375 messages)
    \item Credit Inward/Salary: 20\% (500 messages)
    \item Authentication OTPs: 15\% (375 messages)
    \item Promotional Spam: 15\% (375 messages)
\end{itemize}
Covering State Bank of India, HDFC Bank, ICICI Bank, Axis Bank, Punjab National Bank, and Bank of Baroda. Real user identities are protected via differential anonymization.

\section{Conclusion}
We presented SMS2Finance, an edge-filtered hybrid extraction framework for bank SMS. By combining on-device heuristic filtering with hybrid NER and deterministic reconciliation, SMS2Finance reduces edge bandwidth by 32.91\% with zero false negatives and achieves a 0.9400 macro F1-score with a 0.0\% false-merge rate.
